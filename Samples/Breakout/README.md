# Breakout (Basalt sample)

Physics, game UI and input actions, built only through the automation API (`build_scene.json`).

- **Ball** — a dynamic sphere with no gravity, no friction and full restitution (`RestitutionCombine = Max`), so
  Jolt does the bouncing. `Breakout.lua` keeps its speed constant, stops it from bouncing almost sideways forever
  and keeps it in the plane of the field. Continuous collision keeps it out of the walls at any speed.
- **Paddle** — a kinematic box moved by the script: where the ball meets it sets the bounce (straight up from the
  middle, steeper toward the edges). Bounce directions are normalized vectors rather than angles, so the game
  never calls the platform's trigonometry and plays identically everywhere.
- **Bricks** — 8 x 5 instances of `Assets/Prefabs/Brick.bprefab` laid out by the script, worth 10 to 50 points by
  row. A brick reports its own breaking (`Events.Emit("BrickBroken", ...)`) and removes itself; a particle burst in
  its color and a sound mark it.
- **Kill zone** — a trigger under the paddle: the ball entering it costs a life.
- **HUD** — UI components: score, lives, a prompt, and a Restart button that is shown and focused on game over
  and after a win (so Space, Enter and the gamepad's A press it too).

**Controls** are input actions (`Input.binput`, written by `build_scene.json` through `project.set inputActions`;
edit them in Project Settings > Input Actions). The script reads `Input.GetAction("MoveX")` and
`Input.IsActionPressed("Launch")` and never names a key:

| Action | Bindings |
|--------|----------|
| `MoveX` (axis) | Left/Right arrows, A/D, the left stick (dead zone 0.2), the D-pad |
| `Launch` (button) | Space, Enter, the gamepad's A, the left mouse button |

The mouse moves the paddle too, by how far it travels across the view (`Input.GetMouseDelta` over
`Input.GetViewSize`), so it feels the same in a window of any size and in the editor's Game view. The cursor is
hidden while you play and comes back for the menu (`Input.SetCursorMode`).

`Autopilot` (a script property) is a demo mode: the paddle follows the ball, aiming at a different spot on each
hit, and serves by itself, so it clears the board on its own given a few minutes of game time.

Scripts (`Assets/Scripts`): `Breakout.lua` (the game), `Ball.lua` (reports what the ball hits) and `Brick.lua`. The
sounds are generated by `scripts/generate_sample_assets.py`; the font is Karla (SIL Open Font License,
`Assets/Fonts/Karla-OFL.txt`).

Play: `build/bin/BasaltRuntime --project Samples/Breakout`.
Rebuild the scene: `build/bin/basalt --project Samples/Breakout batch Samples/Breakout/build_scene.json`.

## The gameplay test

`test_game.json` (run by ctest as `SampleBreakout`):

- checks the scene before play (the ball floats and bounces fully, the paddle is kinematic, the kill zone is a
  trigger, the Restart button is wired to the game and hidden);
- drives the paddle with keys (Right, then A back; D and Left together cancel; it stops at the wall), a gamepad stick
  (nothing inside the dead zone, full speed pushed all the way), the D-pad, and the mouse (a tenth of the view moves
  it a tenth of `MouseTravel`);
- rebinds `MoveX` from Lua (`Input.SetBindings`): the old keys stop working and the new ones move the paddle, until
  `Input.ResetBindings`;
- launches with Space and lets the autopilot play 20 seconds: bricks break, the score matches the HUD, the ball
  keeps its speed and never drops, and `events.poll` sees it hit the paddle and the bricks;
- drops the ball into the kill zone (a life lost), serves again with a gamepad's A, then loses the last life: game
  over, the menu is shown and focused, the cursor is back; clicking Restart starts a new game without serving (the
  press lands during game over, which ignores it; the button restarts on release);
- launches with a mouse click, breaks the last brick (a win), restarts with Space on the focused button (a press,
  which the new game waits out so holding Space does not also serve); and finally checks that stopping restores the
  edit scene.
