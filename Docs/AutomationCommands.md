# Automation Commands

Generated by `scripts/generate_docs.py` from `basalt help` — do not edit by hand.

Every command is available through the `basalt` CLI and the editor's TCP server (127.0.0.1:7420).
See `.claude/skills/basalt-make-game/SKILL.md` for the workflow and [MCP.md](MCP.md) for MCP clients.
`basalt help <command>` returns the same `inputSchema` used by request validation and MCP tool discovery.
Commands reject parameters they do not list. In a batch, a request with `"expectError": "<text>"`
succeeds only if its command fails with an error containing `<text>` (used by tests).

## animator

### `animator.retarget`

How an Animator's named ClipLibraries map onto its model, resolved as playback resolves them but without baking (a listed clip can still be left out when it fails to bake or passes the 256 MiB per-Animator budget; the log reports it): per library its index in ClipLibraries, why it adds no clips (error), the joint pairs (target, source, matched by joint map, name or humanoid bone), the model's humanoid bones left unmatched, the root pair with its leg-length scale, the clips it adds, the clips earlier clips hide, and warnings. Read-only; works in edit mode.

### `asset.preload`

Requests mesh/texture CPU loads on the shared worker pool. A .bmaterial is read at once and its textures are requested too (each reported as its own path after the requested ones; one whose UUID does not resolve is failed). Returns a status (pending, ready or failed) and error for each path. Poll by repeating in a persistent serve/mcp/editor session; use wait=true for one-shot CLI calls. wait=true joins these requests, including embedded image dependencies. Reload/refresh retries failed loads. GPU upload happens in the renderer.

|-----------|--------------------|

### `asset.refresh`

Reloads the asset files changed on disk since changes were last reported (by an earlier refresh, by the editor's automatic reload, or since the project was opened in this process): models, textures, animation graphs and material files load again on their next use (graphs restart from their initial state and parameter defaults), and while the game runs (Play, not Simulate) changed scripts are hot reloaded (instances keep their fields; OnReload is called). With 'paths', reloads those files instead, changed or not (a path that does not exist and was not known is an error, and nothing is reloaded then). Files the session wrote itself (asset.write, scene.save, ...) are not reported again. Without 'paths', fails when Assets/ cannot be read.

| Parameter | Type / description |
|-----------|--------------------|
| `paths` | array of project-relative file paths, optional |

<details><summary>Parameter JSON Schema</summary>

```json
{
  "additionalProperties": false,
  "properties": {
    "paths": {
      "description": "array of project-relative file paths, optional",
      "items": {
        "description": "string",
        "minLength": 1,
        "type": "string"
      },
      "type": "array"
    }
  },
  "required": [],
  "type": "object"
}
```

</details>
